## ⚠️ 필수 사항 — 미준수 시 감점

### 1. 샘플링 및 분할 규정

**순서: 샘플링 먼저 → 데이터 분할**

#### ① 서브그래프(Sub-graph) 샘플링 전략
- **무작위 추출 금지**: 단순 무작위 추출은 노드 간 연결성을 파괴하여 GNN 학습 불가 → **금지**
- **밀도 중심 샘플링**: 관계가 조밀하게 엮인 **1만 개 ~ 5만 개** 사이의 노드를 추출
- 추천 전략 (여러 개 조합 또는 다른 전략 사용 가능):
  - **전략 A**: 리뷰가 집중된 상위 N개 식당(Product) 중심 추출
  - **전략 B**: 왕성하게 활동하는 상위 N명 유저(User) 중심 추출
  - **전략 C**: 특정 연도/월 등 특정 타임라인(Time-window) 중심 추출

#### ② 데이터 분할 규칙
- **분할 시점**: 샘플링 완료된 서브그래프 내에서만 분할
- **분할 비율**: 학습용 **80%** (train/valid 비율은 80% 안에서 자유), 시험용 **20%**
- **재현성 확보**: 분할에 사용한 코드와 `random_state` 등 하이퍼파라미터를 **보고서에 명시 필수**

### 3. GNN 모델 사용 필수

- 단순 머신러닝/딥러닝 모델만 단독 사용 시 **큰 감점**
- **GNN 계열 모델을 핵심**으로 사용해야 함

#### GNN 모델 구조 설계 조건

| 구성 요소 | 조건 |
|----------|------|
| **노드** | 리뷰 단위로 고정 |
| **엣지** | 기본 Relation 1개 + 커스텀 Relation 1개 이상 |

#### 기본 Relation (택 1 필수)
- **R-U-R** (Review-User-Review): 같은 사용자가 작성한 리뷰끼리 연결
- **R-T-R** (Review-Time-Review): 같은 식당/호텔에 대해 같은 달에 작성된 리뷰끼리 연결
- **R-S-R** (Review-Star-Review): 같은 식당/호텔에 대해 같은 별점을 준 리뷰끼리 연결

#### 커스텀 Relation (창의성 평가 요소)
- 팀의 도메인 지식과 아이디어를 발휘하여 **창의적으로 설계**
- 제공된 데이터셋(YelpChi, Amazon)은 참고 자료일 뿐이므로, **새로운 연결 방식과 파생 변수** 설정 권장

## 📊 데이터셋

### 메인 데이터셋: YelpZip
- 링크: https://www.kaggle.com/datasets/vaibhavsonkar/yelpzip
- 약 60만 개 이상의 대규모 식당 및 비즈니스 리뷰 원본 데이터

| 컬럼 | 설명 |
|------|------|
| `text` | 리뷰 원본 텍스트 (BERT 등으로 임베딩 추출, 대시보드 사기 증거로 활용) |
| `user_id` | 리뷰 작성 유저 고유 식별자 |
| `prod_id` | 대상 식당/상품 고유 식별자 |
| `label` | 타겟 변수: 사기(1) / 정상(0) — **전처리 후 기준** |
| `date` | 리뷰 작성 날짜 |
| `rating` | 별점 (1~5점), 노드 추가 정보로 활용 가능 |
| `tag` | 리뷰 메타 태그 정보 |

### 참고 데이터셋
- **YelpChi** — 시카고 지역 식당/호텔 리뷰, 스팸 리뷰 탐지 (R-U-R, R-T-R, R-S-R 엣지 구조 참고)
- **Amazon** — 아마존 악기 카테고리, 사기꾼 사용자 탐지 (U-P-U, U-S-U, U-V-U 엣지 구조 참고)
